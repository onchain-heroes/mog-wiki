# MoG Field Guide

- This repository is an independent static player wiki. Read `docs/content-policy.md` before changing content and `docs/architecture.md` before changing the stack.
- The approved content scope is player-visible MoG V2 Arcade information in English, French, Spanish, Japanese, Korean and Simplified Chinese, including the complete reachable bestiary, floor membership, special cells and explanatory visuals. Observable behavior may be verified against runtime code; a tooltip is not required. Game-source imports may be used only in ignored local capture tooling; never include source, secrets, raw configuration, hidden probabilities or unreleased content in the public wiki.
- Private evidence and drafts belong in ignored `.local/`, never in article metadata, comments or public assets. Files outside the site build may still be visible if committed to a public repository.
- Prefer ordinary Markdown and the existing Starlight features. Keep JavaScript, dependencies and component overrides small.
- Use local Node `24.20.0` and pnpm `11.24.0`, as pinned in the repository. Vercel uses Node `24.x` and `ENABLE_EXPERIMENTAL_COREPACK=1` to honor `packageManager`. Run `mise exec -- pm run validate` for changes, and check the built site when modifying search or navigation.
- Keep Grid and List views working on all four catalogues, with a shared remembered choice, preserved filters and selection, and a complete readable list without JavaScript.
- Keep claims limited to verified source/UI behavior. A local source review is not proof of current live gameplay.
- The public source repository is `https://github.com/slkzgm/mog-wiki`; the production origin is `https://mog-wiki.vercel.app`. GitHub-to-Vercel publication uses `main` for production and pull requests for previews. `vercel.json` installs with a frozen lockfile, runs `pnpm run build` and publishes only `dist/`. Keep Astro's `site`, Starlight's sitemap and this origin consistent; production is indexable and `VERCEL_ENV=preview` retains `noindex, nofollow` metadata.
- Local implementation does not authorize future publication or deployment. Obtain authorization before actions that publish source or trigger deployments; explicit authorization in the current task takes precedence. Verify the deployed commit and hosted behavior separately from local validation or CI, and never describe an unverified deployment as successful.
